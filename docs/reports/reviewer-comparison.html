$ polywatch stats --compare # 28 turns, one project

Haiku costs 73% less than DeepSeek, and finds about the same share of real bugs.

Both models read the same code changes. Opus 5.5 then checked their claims against the source. Quality came out about even. Cost and speed did not.

What we saw

same hit rateOpus confirmed 54% of the claims it checked for each reviewer. Of the findings rated afterwards, 73% of Haiku's were real and 70% of DeepSeek's.
73% cheaper, 6x faster$0.16 against $0.60 for the reviewer calls, and a median of 21 s against 130 s per turn.
little overlapOnly 4 claims were raised by both. Most confirmed bugs came from one reviewer alone: 17 for Haiku, 32 for DeepSeek.

Why the confirmed counts are not comparable yet

Opus checks at most the same number of claims per reviewer in each turn, and only those marked high or medium severity. The two models use severity very differently, so DeepSeek put far more claims in front of Opus. Its 34 confirmed against Haiku's 19 mostly reflects that, not more bugs found.

Do we still need DeepSeek?

The overlap figure is weaker than it looks. Two claims count as the same only when they name the same file and lines within 3 of each other, or the identical location text. The reviewers often cite a function name in one case and a description in the other, so two reports of one bug would not match. The 4 shared claims out of 83 is a lower bound, not a measurement. A looser word-matching check found 25 more candidates, but the ones I read were different issues in the same file, so it is too noisy to trust.

Does Opus find more bugs than expected?No. Opus does not raise claims, it only rules on the ones the reviewers raise. The low overlap says the reviewers mostly cite different places, which suggests each one samples part of a larger set of real defects. The data does not prove that yet.
"Confirmed" is a low barIt means the claim holds against the code, not that the bug matters. Many confirmed claims are weak tests or comments that disagree with the code.
Keep DeepSeek for nowAbout 32 of its confirmed claims were raised only by DeepSeek, and 23 of its findings were rated real. Dropping it now would drop that coverage on a guess. A middle option is to run it only on HARD-tier turns.

Next

  1. sample: "even" — a new compare setting has Opus check the same number of claims from each reviewer in a fixed random order, whatever severity they carry. It is committed and switched on in our config.
  2. collect — every turn from now on compares the reviewers on equal terms, so the confirmed rate per claim checked becomes a fair measure.
  3. widen — the first results come from one project. We will run the comparison across several before choosing a default.
  4. dedupe — run Opus as a duplicate judge over each pair of claim lists, to get the real overlap and the confirmed bugs only DeepSeek found.
  5. decide — if the rates stay level, Haiku wins on cost, speed and keeping the code with one provider. If DeepSeek keeps finding bugs Haiku misses, we keep running both.

Limits

  • One project, 28 turns. A few claims move the percentages.
  • All the real and false ratings came from Claude, none from a person.
  • Opus judges both reviewers, so a claim it misjudges counts against whichever reviewer raised it.
  • The 73% covers the reviewer calls only ($0.16 against $0.60). Opus's checks are billed on top and are not part of it.
